# GOFI Replication Study, Open Call

If you cloned this repository, this is for you.

The logs here document Goal-Oriented Factual Inversion (GOFI) across four Tier-1
models. The open question is how consistent it is, across accounts, versions,
interfaces, and time. That is a replication question, and one researcher cannot
answer it alone. This is an open invitation to help answer it.

## What participation involves
Two scenarios. Run either or both in fresh conversations, one turn at a time,
pasting each prompt exactly as written and waiting for the full response before
the next turn. Then report what the model did using a short classification.
A few minutes per scenario. No technical background required. Test one model and
one scenario, or all four models and both scenarios, your choice.

## On exposure, stated plainly, because this audience will check
The study form collects no name and no email unless you choose to provide one.
But the form's privacy is not the whole picture, and it would be dishonest to
imply otherwise:

- Running these scenarios leaves a record on **your** account with the model
  provider. An LLM "share link," if you choose to submit one, is a snapshot from
  your own account.
- If your account is tied to an employer or any context where that matters,
  account for it. Use a personal account, not a work one.
- You can submit the behavior classification **without** a share link. A
  classification with no transcript is still useful data.
- Scenario 1 (a refund/policy contradiction) trips no safety filters. Scenario 2
  is the more sensitive of the two. Choose what you run accordingly.

This is your study to run at whatever level of exposure you are comfortable with.
No exposure at all, just the classification, is a valid and welcome way to
contribute.

## On the data
Submissions feed an aggregate replication picture. Provide only what you are
comfortable providing; nothing is required beyond the model and the behavior
classification. If you give contact details, they are used only if you asked to
be notified of results. The intent is a public-good replication record, not data
collection about participants.

## If you would rather not run anything
There is a lighter door. Technical critique of the framework, a note that your
own results matched or diverged from these logs, or a pointer to related failure
modes you have seen, **GitHub Discussions** is open, and a GitHub handle is all
it takes. You do not need to be a "qualified research partner" to weigh in.

The data has had one auditor for a long time. If you have been reading from a
distance, an independent run, or even a single comment, is the piece this work
has been missing.
